# 「更顺手」设计：界面基础 + 六个日常功能

日期：2026-11-15　状态：待用户批准

## 意图和原因

Voxel 已公开发布（v0.1.1）。下一步的目标是**让陌生玩家愿意长期用下去，并且信任它**：不是堆功能，而是让日常操作快、细、稳，让人第一次用就觉得“这个启动器靠谱”。

用户已选定：方向 A（更顺手）里的六项功能，以及“界面细节”（统一动效节奏、紧凑模式、界面缩放、键盘全程可操作），后者被明确标为重要。

## 目标

1. **界面基础先行**：动效有统一节奏；有舒适/紧凑两种密度；界面可缩放；整个软件可以只用键盘操作。
2. **全局搜索（Ctrl+K）**：找实例、存档、服务器、设置和常用操作，回车即执行。
3. **拖拽安装**：把文件拖进窗口就装好（模组 jar、整合包 mrpack、光影或资源包 zip）。
4. **任务中心**：一个入口看到所有进行中和刚完成的任务，能取消。
5. **更强的日志查看器**：搜索、按级别过滤、一键复制报错。
6. **系统通知**：游戏崩溃、下载完成时，在窗口不在前台时弹 Windows 通知。
7. **实例详情页**：一个实例的模组、存档、截图、日志、设置集中在一页。
8. **可信度（我加的，小）**：在“关于”里增加“透明度”说明——启动器会连哪些网站、为什么、数据存在哪；并检查常见错误提示是否都是人话。

## 非目标和反目标

- 不重做现有导航，不删除任何现有页面（实例详情页是新增，不是替换）。
- 不做并行任务（保持“一次只做一件大事”），任务中心只是把它们看得更清楚。
- 不做拼音搜索、不接 CurseForge、不做代码签名、不做微软登录和皮肤（用户已暂缓）。
- **反目标**：任何会阻塞操作的动效；任何把数据发出本机的新功能（不加统计、不加遥测）；让已有流程变慢或变得更难找。

## 约束

- 沿用现有技术栈：Tauri 2、React、Tailwind v4、shadcn/Base UI；仅 Windows；不引入大型新依赖（系统通知用官方插件，是唯一新增）。
- 界面偏好（密度、缩放、通知开关）存在本机，不进入账号或设置文件。
- 性能：250 个模组的列表和 3000 行日志必须流畅（需要窗口化渲染）。
- 无障碍：尊重“减弱动效”；所有可点击元素可聚焦，有可见的焦点环。
- 新的后端逻辑要有 Rust 测试；界面用浏览器模拟数据验证。

## 考虑过的做法和取舍

**界面缩放**
- A. CSS `zoom` 缩放根节点。简单，但弹窗等挂在根节点外的元素会不一致，且文字可能发虚。
- B. **Tauri 的 webview 缩放（推荐）**。就是浏览器级的真缩放，文字清晰，弹窗一并缩放；快捷键 Ctrl+加号/减号/0。浏览器预览里退回 A。
- C. 全部改成 rem 单位。最干净但要改遍所有样式，风险大。
→ 选 B。

**紧凑模式**：把间距、圆角、行高收进几个 CSS 变量，只让共用组件（Bezel、按钮、列表行）读取；不逐页重写。

**拖拽**：用 Tauri 的拖放事件拿到文件路径。拖入后**先弹一个确认框**列出“将把什么装到哪个实例”，回车确认才复制，装完 8 秒内可撤销。不静默写文件，这是信任问题。

**任务中心**：任务状态仍由前端的统一状态收集（已有“当前任务”机制），做成标题栏图标加弹出层；不改后端的“一次一件事”。

**实例详情页**：复用现有的存档、截图、备份、模组等组件（它们大多已经接受“某个实例”作为参数），把内容页里的“已安装”部分抽成可嵌入的组件。

## 各功能要点

**界面基础**
- 动效：统一为三档时长（快 150ms、常规 300ms、慢 600ms）和现有缓动曲线，收进 CSS 变量和一个共用的动效文件，全局审查并替换零散写死的数值。
- 密度：设置里“舒适/紧凑”。缩放：80%–150%。
- 键盘：全程可聚焦，焦点环用像素风；侧边栏用方向键切换；分段控件、列表支持方向键；Ctrl+K 搜索，Ctrl+1…7 切页，`?` 显示快捷键帮助；Esc 关闭一切弹层。
- 设置里新增“界面”分区：密度、缩放、减弱动效跟随系统、快捷键说明。

**全局搜索**：数据来自已有状态（实例、服务器、页面、动作），存档按需读取。结果分组，上下键选择，回车执行，Esc 关闭，最近用过的排前。运行中的实例不可重复启动。

**拖拽安装**
- `.jar` 装进当前实例 mods（需要加载器；重名自动加序号，不覆盖）。
- `.mrpack` 导入为新实例（需要新增“导入本地整合包”的后端，复用已有整合包安装逻辑）。
- `.zip` 判断是光影还是资源包（看内部结构），判断不了就询问。
- 游戏运行中拒绝；一次拖多个文件合并成一个确认框；路径全部走现有的安全拼接。

**任务中心**：标题栏图标显示进行中数量；弹出层列出当前任务（进度、速度、取消）和最近 10 条结果（成功或失败、时间）。

**日志查看器**：识别 `[时间] [线程/级别]:` 格式；级别过滤、搜索（高亮、上下一个匹配）、换行开关、手动上滚时暂停自动滚动、窗口化渲染；复制可见行、全部、或“报错摘要”（第一段 ERROR 及其堆栈）。

**系统通知**：官方通知插件。只在窗口未在前台时发：游戏崩溃（带诊断标题）、安装或下载完成。设置里可关，默认开。

**实例详情页**：新页面 `instance`；头部（封面、名称、版本、加载器、启动或结束）；标签：概览（游玩时长、最近备份、问题提示）、模组、存档、截图、日志、设置。入口：点击实例卡片；原有启动按钮不变。

## 实施顺序（及理由）

1. 界面基础（影响所有后面的页面，先做）；2. 全局搜索；3. 日志查看器；4. 任务中心和系统通知；5. 拖拽安装；6. 实例详情页；7. 透明度说明和整体走查。

## 我替用户做的决定（请检查）

1. 缩放用 webview 真缩放；紧凑模式只改共用组件。
2. 拖拽一律先确认再写文件，并提供 8 秒撤销。
3. 通知只在窗口不在前台时发，默认开，可关。
4. 任务中心不改“一次一件事”的限制。
5. 界面偏好存本机，不进设置文件。
6. 实例详情页复用现有组件，原有页面保留。
7. 不做拼音搜索。
8. 增加“透明度”说明（原请求里没有，为“让陌生人信任”而加）。

## 留给实现者的

具体像素尺寸和色值；快捷键冲突的细节（与游戏无关，只在启动器窗口内生效）；本地 mrpack 导入对“缺少下载地址”的错误文案；窗口化渲染的具体实现方式。

## 风险

- 动效审查会触及很多文件，需要逐页看过，防止改坏已有的观感。
- 本地整合包导入是唯一较大的新后端工作，要注意校验和路径安全。
- 系统通知的点击行为在 Windows 上受插件限制，只保证“弹出”，不保证“点击后跳转”。
